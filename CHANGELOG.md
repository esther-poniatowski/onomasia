# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/),
and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `onomasia:glossary@2` and `onomasia:notation@2`, whose key `from` names the source of an import by
  an identifier, or by a logical target of Anagraphe `{repository, id}` for a record of another
  repository. The target form declares `x-target-contract` with the contract of the importing
  record. The schema registry exports both new versions.
- `onomasia:overlay@2`, whose key `overlays` names the notation to change by an identifier, or by a
  logical target `{repository, id}`. The schema declares `x-target-contract: ['onomasia:notation']`
  at that key. The composer reads that notation as it reads the source of an import. An output
  names its notations by their identifiers in the consumer. Therefore, an output naming an overlay
  of a notation of another repository is reported as `unresolved-output`. The schema registry
  exports `onomasia:overlay@2`, and `onomasia:overlay@1` stays readable.
- In `onomasia:notation@2`, `denotes` holds a logical target naming a unit. Onomasia normalizes the
  target by the repository holding the notation. A text under `denotes` of `onomasia:notation@1`
  still declares its entry, and carries no target.
- The composer reads each source of another repository through the record resolver of Anagraphe,
  at the state selected by the resolution context of the consumer. The composer keys each record
  by its repository, its commit and its identifier. A repeated record is read once. A cycle
  across repositories is reported as `import-cycle`.
- Each finding of the resolver is reported at the key `from` of its import, under the kind of the
  finding. A finding is an error by default when it leaves the source unread.
- The section `imports` of `onomasia.yml` limits the closure of each record: 8 levels, 64 records
  and 4 MiB of record bytes by default. An exceeded limit is reported as `import-limit`.
- The optional block `inputs` of each generated document lists the records of other repositories
  imported into its records, each with its commit and its `sha256` digest.
- The LaTeX package and the MathJax preamble state one comment line per input after their sources,
  written `% repository commit id sha256`. The Python expander holds the inputs in its constant
  `INPUTS`.
- In `onomasia:term-table@1`, the `gloss` of a term read from another repository gains the
  optional fields `repository` and `commit`. Its `resource` is the path of the record within that
  repository.
- The check `unnormalized-target` reports a unit target naming no repository, in a repository
  declaring no identifier.
- `check_records` and `build_outputs` accept a state provider of Anagraphe under the keyword
  `provider`. The new function `default_provider()` returns the Git provider of Anagraphe, reading
  the clones of the machine, then its cache. The commands pass that provider.
- The schema registry `specs/schema-registry.yml`, generated by Kleisis, exports
  `onomasia:glossary@1`, `onomasia:notation@1` and `onomasia:overlay@1`, so that a repository can
  import their schemas at a pinned commit and Ekphrasis can validate its glossaries, notations and
  overlays.
- The schemas of `onomasia:glossary@1` and `onomasia:notation@1` declare `x-identifier: id`, so
  that Anagraphe reads the identifier of a glossary or a notation from its root key `id`, and a
  logical target can name it. The annotation changes no valid record.
- `onomasia check` and `onomasia build` take `--format sarif`, which writes the issues as a
  findings log in the profile of the gate Elenchos, and `--output`, which names its file. A defect
  in a text takes the typed locus `term:<glossary>` or `symbol:<notation>` and the form matched as
  its discriminator.
- The cases `specs/cases/sources.yml` fix the meaning of the common field `sources` for every
  producer of a document of the contracts of Onomasia. The cases cover the values admitted by the
  schema, the location written for a remote, and the value of `dirty` for each state of a
  repository.

### Changed

- **Breaking:** Hodegos locates the root of a command and the file `onomasia.yml`. The file lies at
  the root, in its subfolder `.config/`, or in a folder that the `hodegos.yml` of the root
  declares. `config/tools/onomasia.yml` is read only when `hodegos.yml` lists `config/tools`.
  `discover_configuration` replaces `find_root` and `locate_configuration`.
- **Breaking:** Onomasia reads Anagraphe only through the interface of its read package
  `anagraphe-read`, which replaces the distribution `anagraphe` as a dependency. Each run opens the
  repository of the consumer with `open_repository`, which resolves and reads the sources of
  imports and the bindings of texts. The identifier of the consumer is the identity that Anagraphe
  derives, from the section `repository` of `anagraphe.yml`, the remote or the folder, instead of
  the retired manifest `repository.yml`. An invalid configuration of Anagraphe now stops every run.
- **Breaking:** Onomasia reads `onomasia:denotes-targets@3` and writes `onomasia:macro-table@2` and
  `onomasia:macro-lookup@2`. A target of the denotes targets may omit `repository`, and then names
  a unit of the consumer: Onomasia normalizes it by the identifier of the consumer. Each unit is
  matched with an entry by its normalized target. The lookup lists its units under `targets` as an array of `{target, name}`, ordered by
  the repository, the identifier and the unit of the target.
- **Breaking:** a unit of `onomasia:denotes-targets@3` states three facts of its domain, and the
  keys `arity`, `binder` and `variadic` are retired:
  - `arguments`, the number of its arguments;
  - `bound`, the slot of its bound variable;
  - `list`, the slot of its list.

  Onomasia derives the arity of a macro from `arguments`, and each entry of
  `onomasia:macro-table@2` gains `list`.
- **Breaking:** every document of the five contracts of Onomasia names its contract under
  `_schema` instead of `contract`, as every record names its format. A registry of schemas can
  therefore select these contracts. A document naming its contract under `contract` is reported by
  `invalid-contract` and skipped.
- The new check `invalid-item` reports an item of an input document breaking its schema, or naming
  a slot outside its unit. Onomasia skips that item and keeps the other items. The check
  `invalid-contract` now covers the header of a document only.
- **Breaking:** `dirty` in `sources` is true when the commit does not hold one of the files read
  to generate the document, and no longer when any file of the working tree changed. The method
  `sources` of a provenance receives the files read beside the root.
- The schemas of `onomasia:glossary@1` and `onomasia:notation@1` move to `glossary.v1.schema.yml`
  and `notation.v1.schema.yml`; Onomasia still reads both versions.
- The schema of `onomasia:overlay@1` moves to `overlay.v1.schema.yml`.
- **Breaking:** `onomasia.yml` names its format under the key `_schema`, as its first key, with the
  value `onomasia:configuration@1`. The key `schema_version` is retired: the command stops with
  status 2 and names the value to write. A file without the key, or with another value, stops the
  same way.
- A term or a notation entry names its replacement under `superseded_by`, formerly
  `replaced_by`, and the packaged status requiring a replacement is `superseded`, formerly
  `deprecated`, as the vault and its tools name them.
- `entry-status` also reports the printed body of a reported entry, with the replacement.
- A printed body opening on a letter matches only where no letter or backslash precedes it.

### Security

- The field `sources` of a built document, and the header of a generated package, name the remote
  of the repository without its user information. A remote such as
  `https://user:token@host/repo.git` is written `https://host/repo.git`, and the user of a remote
  in the form `user@host:path` is dropped, so that a committed document holds no credential.

### Dependencies

- Merismos at commit `feb6654`, which reads Markdown as observed in Obsidian 1.15.0, and Anagraphe
  at commit `97a5850`, after its release `v0.3.1`, which pins the same Merismos and reads its
  configuration under the key `_schema`.

### Added

- A lexical rule and a notation entry may carry `metadata`, as a term does.
- A form may be written as an object, `{literal: …}` or `{regex: …}`, with a `description`.
- A replacement may state its `condition`, printed in the advice of `forbidden-form`.
- Each character of a masked region reads as U+0000, which an expression may name.
- Without `--config`, `check` and `build` read `config/tools/onomasia.yml` or `onomasia.yml`
  below the root. When both files exist, the command stops with status 2 and names both; when
  neither exists, the message names both places. A given `--config` is read from the current
  folder, as before, and an absent file is an error.
- Without `--root`, the root is read from the new environment variable `ONOMASIA_ROOT`, and
  otherwise is the nearest folder, from the current one upwards, holding one of both files, and
  otherwise the current folder, formerly always the current folder.
- The short options `-r` for `--root` and `-c` for `--config`.
